## Why

The Simprints fork is currently based on `develop-eyeseetea` 3.4.1
(`3.4.1-simprints-fork-1`), while the shared baseline has moved to **3.4.2**
(`develop-eyeseetea@f87bec8c3`). Staying behind the baseline means missing
upstream Oslo fixes and, in this case, several EyeSeeTea-wide improvements
already merged on top of 3.4.2 — including a baseline extension point
(`PostMetadataSyncAction`) that directly fixes an accepted regression the
3.4.1 upgrade shipped with. Closing the gap now, while it is still small (9
Oslo commits plus 5 EyeSeeTea PRs since the 3.4.1 merge-base), keeps the
upgrade cheap.

## What Changes

- Merge `develop-eyeseetea@f87bec8c3` (3.4.2 Oslo baseline plus EyeSeeTea PRs
  #326, #328, #329, #330, #331) into `feature-simprints/upgrade_3.4.2`, moving
  the implementation baseline for all 13 active Simprints customizations from
  3.4.1 to 3.4.2.
- Classify every conflicted and non-conflicted-but-customization-touching
  file per `eyeseetea-docs/upgrade/conflict-rules.md`
  (`accept_ours` / `accept_theirs` / `manual_reapply_on_theirs` /
  `defer_after_build_verification`).
- Resolve `accept_ours` / `accept_theirs` files first, then manually reapply
  Simprints logic on top of the new baseline for `manual_reapply_on_theirs`
  files.
- Verify the 3.4.1-upgrade improvements already promoted to baseline still
  hold after the merge:
  - `PostMetadataSyncAction` (B4/B5, landed in `4e5635da5`) — confirm
    `app/src/simprints/.../PostMetadataSyncModule.kt` still matches baseline's
    contract and still fixes the metadata-sync biometrics-config regression.
  - `AGENTS-<client>.md` import convention (B1, landed in `f87bec8c3`) —
    confirm the merge doesn't reintroduce a fork-owned `CLAUDE.md`.
- Run the automerge verification rule from `AGENTS.md` /
  `conflict-rules.md` for every file listed in `customization-files.md`, not
  only files git marks as conflicted.
- Confirm the areas explicitly out of scope for preservation (2FA/login,
  notifications, change server URL, granular sync flavor wiring) still match
  baseline behavior.
- Validate the result against
  `eyeseetea-docs/upgrade/simprints/upgrade-validation-checklist.md`.
- Update `customization-files.md` with confirmed surviving customizations
  and close out `eyeseetea-docs/upgrade/simprints/upgrade-3.4.2-notes.md`.

No **BREAKING** changes to Simprints-facing behavior are intended — see
Capabilities below.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. This change intentionally preserves all 13 active Simprints
capabilities unchanged at the requirements level (`openspec/specs/`) — only
the implementation baseline moves from 3.4.1 to 3.4.2. If resolving a
`manual_reapply_on_theirs` conflict surfaces a genuine behavior change that
cannot be avoided, that is out of scope for this change and must be raised
with the user and proposed separately, not folded silently into the upgrade.

This change sets `skip_specs: true` in `.openspec.yaml` accordingly.

## Impact

- **Flavor source set (`app/src/simprints/`, `app/src/simprintsDebug/`)**:
  low conflict risk — isolated from upstream by construction. One file to
  double-check regardless of conflict status:
  `app/src/simprints/.../PostMetadataSyncModule.kt`, now consuming a baseline
  contract that stabilized after the 3.4.1 merge.
- **Shared code (`app/src/main/...`)**: expected conflict surface is smaller
  than the 3.4.1 upgrade — 9 Oslo commits (`origin/upstream/3.4.1..origin/upstream/3.4.2`)
  plus 5 EyeSeeTea PRs, versus a full Oslo minor version last time. The one
  Oslo commit with plausible overlap with an active capability is
  `dd88b0b51` ("use aggregated syncState for sync button in search list",
  `ANDROAPP-7682`) — touches the search/list area that
  `biometric-search-integration` and `biometrics-tei-ui-surfaces` depend on;
  check for conflicts or silent drift in `SearchTEIViewModel.kt` /
  `SearchTeiModel`-adjacent files.
- **Baseline extension points now stable**: `PostMetadataSyncAction`
  (`:commonskmm`, `:sync`) is no longer newly-landed — verify its contract
  didn't change shape and Simprints' registration still compiles as-is.
- **Areas to remove, not preserve**: unchanged from 3.4.1 — `login/` Dagger
  remnants, `data/notifications/`, `usescases/notifications/`,
  `utils/session/ChangeServerURL*`, granular sync flavor wiring.
- **Build/dependency files**: `app/build.gradle.kts`, `settings.gradle.kts`,
  `gradle/libs.versions.toml` — re-check flavor/composite-build blocks against
  the new baseline; one Oslo commit in this range bumps the SDK to
  `1.14.2-SNAPSHOT` (`643e66591`), relevant to the SDK-fork substitution setup.
- **OpenSpec/Claude scaffolding**: baseline's `.claude/skills/openspec-*` is
  still generated by CLI `1.2.0` (B3, still `pending`) while this fork's copy
  is already `1.8.0` — expect the same `AA` add/add conflicts seen in the
  3.4.1 merge on these files; resolve `accept_ours` as before.
- **Tests**: `SearchTEIViewModelTest.kt`, `SyncMetadataTest.kt`-adjacent
  fork tests — expect updates wherever a manual-reapply file changes.

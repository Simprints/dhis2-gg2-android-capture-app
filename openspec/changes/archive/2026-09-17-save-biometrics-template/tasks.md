## 5. Hide the attribute

- [x] ~~5.1 Design and create the DHIS2 program rule (metadata, external) that hides the new template attribute...~~ **Reverted.** Originally implemented as two `HIDEFIELD` program rules (`cqYE1buKkxg` on `0.0 General Registration`, `W9yagzFawV1` on `1.6 Child Health`, both `condition: "true"`), per PM guidance to avoid a hardcoded type-check filter. On-device end-to-end testing found this breaks the write this whole change exists to make: `RulesUtilsProviderImpl.hideField()` sets the hidden attribute's value to `null` on every form save, which silently wiped the template written moments earlier by `updateBiometricTemplateAttributeValue` — confirmed via `blockingSetCheck result=true` immediately followed by the value's absence in the local DB once enrollment finished saving. See design.md "Hiding mechanism" decision. Both program rules were deleted from `simprints-dev`.
- [x] 5.2 Hide the field by code instead: filter `biometricTemplateAttributeId` out of the field list in `EnrollmentPresenterImpl.onFieldsLoading()`, alongside the existing `BiometricsAttributeUiModelImpl` filter. Verify: opening the enrollment form does not show the template field, and the value written during `onBiometricsCompleted()` survives completing/saving the enrollment. **Done**: verified on a real device — template value present in the local DB and, after sync, on the server, after completing the enrollment form.

Commit: app code change (`EnrollmentPresenterImpl.kt`) plus the program rule deletions (metadata, external) — one commit, since 5.1's revert and 5.2's fix are the same change in practice.
